   - 진행 중, 확인 필요, 외부 응답 대기, 완료 상태를 필터링할 수 있도록 유지했다.

   - 상태색은 작은 상태점과 진행선에만 사용하고 완료 작업은 저채도 회색으로 표시했다.

   - 이전 단계 스냅숏, 정정 분기, 자동화 실행 이력은 기존 문맥을 보존하는 방식으로 유지했다.

   - 작업별 챗봇 대신 자동화가 멈춘 이유와 필요한 입력을 구조화된 폼으로 제시한다.

[2026-09-02] 단계별 신규 작업 배지 및 사이드바 조작성 개선

1. 단계별 신규 작업 배지
   - MR 목록, 협력사 선정, PO 관리 메뉴 우측에 아직 열어보지 않은 신규 작업 수를 표시한다.
   - 배지는 붉은 배경, 흰 글씨, 완전한 라운드 형태로 통일했다.
   - 숫자 자릿수가 달라져도 메뉴명과 아이콘 위치가 밀리지 않도록 우측 정렬과 고정 높이를 적용했다.
   - 활성 메뉴에서도 배지 색상이 흐려지지 않고 동일한 빨간색을 유지한다.
   - 사이드바가 접힌 상태에서는 아이콘 우측 상단에 작은 배지로 재배치된다.

2. 확인한 작업 처리
   - MR 목록, 협력사 선정, PO 관리 메뉴를 열면 해당 단계의 신규 작업 배지가 사라진다.
   - 확인하지 않은 다른 단계의 배지는 그대로 유지한다.
   - 작업이 한 단계에서 빠지면 해당 단계의 확인 기록도 정리한다.
   - 동일 작업이 이후 그 단계로 다시 들어오면 새로운 작업으로 다시 안내한다.
   - 현재 열어둔 화면으로 새 작업이 들어오면 이미 화면에서 확인 가능한 상태이므로 자동으로 읽음 처리한다.

3. 사이드바 접기 버튼 복구
   - 접기 버튼이 본문 레이어 아래에 가려져 일부만 보이던 문제를 수정했다.
   - 사이드바와 접기 버튼의 z-index, overflow, 크기, 테두리 대비와 그림자를 조정했다.
   - 펼친 상태와 접힌 상태 모두 오른쪽 경계에서 온전한 원형 버튼으로 보이도록 유지했다.

4. 보관용 작업 노출 방지
   - ERPNext가 삭제된 MR 번호를 재사용할 때 생성되는 #archived-* 감사 이력을 현재 작업 화면에서 제외했다.
   - 완료·취소·반려 케이스가 ERP 상태값 때문에 대시보드에 다시 나타나지 않도록 필터 순서를 보강했다.

5. API 모드 초기 표시 안정화
   - 실제 API 모드에서는 협력사·PO 목업 데이터로 배지가 순간적으로 표시되지 않도록 초기 배열을 비워둔다.
   - 백엔드 조회가 완료된 뒤 실제 단계별 작업 수만 배지에 반영한다.

   - RFQ 발송 완료, 협력사 최종 선정, 마감 연장 완료 안내를 native alert 대신

[2026-09-02] 단계 오인 방지 및 실제 API 상태 전환 보강

1. 구형 상태 매핑 교정
   - awaiting_supplier_approval을 PO 승인 단계가 아닌 RFQ 협력사 선택 단계로 수정했다.
   - 나머지 LangGraph 내부 상태도 안정적인 화면 단계와 상태로 명시적으로 변환한다.

2. API 모드의 목업 성공 폴백 차단
   - RFQ 발송, 업체 선정, 발주 시작, PO 승인, Scorecard 제출 시 실제 pending task가
     없으면 화면만 성공 처리하지 않고 오류를 안내한다.
   - 모든 작업 응답에 task version을 전송하여 중복 클릭과 오래된 화면의 응답을 막는다.
   - 대시보드 승인 버튼도 실제 케이스 시작 API를 호출한다.

3. 단계별 버튼 활성 조건 보강
   - RFQ 구성은 RFQ_TARGET_SELECTION에서만 활성화한다.
   - 견적 업체 선정은 QUOTATION_COLLECTION/SUPPLIER_SELECTION에서만 활성화한다.
   - 발주 시작은 ORDER_START에서만 활성화한다.
   - 업체 선정 모달은 실제 회신한 업체만 기본 선택 및 확정할 수 있다.
   - AI 검색 결과가 없을 때 사용자가 공급사명과 이메일을 직접 추가할 수 있다.

4. 화면 지표 정합성 개선
