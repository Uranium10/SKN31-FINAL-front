[2026-08-24] 중간 발표용 구매 업무 UX 개편

1. 통합 작업함 전환
   - 개인별 카테고리 분류·작업 이관 시나리오를 발표 범위에서 제거했다.
   - ERPNext에서 수신한 모든 MR을 한 명의 구매 담당자가 처리하는 통합 작업함으로 구성했다.
   - 진행 중, 확인 필요, 외부 응답 대기, 완료 상태를 필터링할 수 있도록 유지했다.

2. 작업 스트립 및 상세 화면 리파인
   - 상단 통계 카드와 중복 연결 표시를 제거하고 작업 목록 중심으로 정보 구조를 단순화했다.
   - 상태색은 작은 상태점과 진행선에만 사용하고 완료 작업은 저채도 회색으로 표시했다.
   - 작업 카드를 누르면 현재 단계 중심의 가로 스크롤 워크플로가 펼쳐지도록 구성했다.
   - 이전 단계 스냅숏, 정정 분기, 자동화 실행 이력은 기존 문맥을 보존하는 방식으로 유지했다.
   - Apple 설정 앱과 Linear 계열의 차분한 시각 위계를 참고해 여백, 서체, 테두리, 그림자를 정리했다.

3. 폼 기반 사용자 인터럽트
   - 작업별 챗봇 대신 자동화가 멈춘 이유와 필요한 입력을 구조화된 폼으로 제시한다.
   - 데이터 정리 예시에서 ERPNext 요청 원문과 적용할 표준값을 함께 비교할 수 있다.
   - 표준값 적용 후 자동화 재개 또는 요청자 보완 요청을 선택할 수 있다.
   - 원문과 사용자 처리 결과는 감사 가능한 자동화 이력으로 보존한다.

4. 전역 도움말 챗봇 복구
   - 작업 실행 세션과 분리된 프로그램 안내용 '도움말 챗봇' 탭을 복구했다.
   - 통합 작업함, 사용자 확인, 알림, Flow Scheduler, RFQ·견적·PO 흐름을 안내한다.
   - 현재는 실제 구매 작업을 실행하지 않는 키워드 기반 목업 응답으로 동작한다.
   - 새 도움말 대화와 최근 도움말 세션 UI를 제공한다.

5. ERPNext 접속자 계정 표시
   - 로그인 성공 후 ERPNext User 문서에서 full_name, 사용자 ID, 이메일, 사용자 유형을 조회한다.
   - 조회한 프로필을 JWT와 브라우저 저장소에 보존해 새로고침과 토큰 갱신 후에도 유지한다.
   - 사이드바 계정 영역과 작업 상세의 처리 담당자에 실제 접속자 이름을 표시한다.
   - Administrator처럼 이메일 형식이 아닌 ERPNext 계정도 동일하게 지원한다.

6. 검증
   - 프론트엔드 npm run build 통과
   - 프론트엔드 npm run lint 통과
   - 백엔드 Python 문법 검사 통과
   - Administrator 토큰 갱신 후 ERPNext 사용자 ID 유지 테스트 통과
   - 1366x768 및 1600x1000 브라우저 렌더링 확인

[2026-08-28] 아이템 등록 화면 해석 정정 및 ERPNext 연동 프로토타입 롤백

1. 화면 역할 정정
   - 아이템 등록 화면은 ERPNext 전체 Item 마스터 조회 화면이 아니라, 협력사 연결 또는 AI 정제를 마친 등록 후보를 사용자가 검토하는 화면으로 확정했다.
   - 기존 목업 데이터 기반의 승인·반려·신규 후보 등록 흐름으로 복원했다.

2. ERP 연동 시도 정리
   - JWT 세션에서 암호화된 ERPNext SID를 복호화해 사용자 권한으로 Item REST API를 호출하는 구조를 검증했다.
   - 실제 환경에서 Item 273건, Item Group 12건, UOM 241건, Asset Category 0건을 읽기 전용으로 확인했다.
   - 라이브 ERPNext Item 생성·수정·삭제는 실행하지 않았다.

3. 후속 설계 기록
   - 후보 아이템과 ERP Item 마스터를 분리하고, 사용자 승인 시에만 ERP Item을 생성하는 권장 흐름을 문서화했다.
   - 상세 기록: FINAL-docs/SKN31_ITEM_REGISTRATION_INTEGRATION_PROTOTYPE_2026-08-28.md

[2026-08-28] 구매 단계별 목업 데이터 분리 및 인터랙션 고도화

1. 단계별 단일 큐 구성
   - MR을 번호 기준으로 중복 제거하고, 현재 처리 단계에 해당하는 화면 한 곳에만 표시되도록 분리했다.
   - 승인 전·반려·협력사 거절 복귀 건은 MR 목록, 승인 및 AI 분석 완료 건은 협력사 선정 화면에 표시한다.
   - 업체 선정과 PR 발송을 마친 건은 협력사 승인 대기 상태로 PO 관리 화면에 이동한다.
   - 협력사 거절로 복귀한 건은 기존 PO 목록에서 제외하고, 재승인 후 다시 협력사 선정 단계로 진입하게 했다.

2. 상태 전환과 사용자 안내
   - MR 승인 시 AI 견적 분석 완료 알림과 함께 협력사 선정용 목업 견적 데이터를 생성한다.
   - 업체 선정 모달 안에서는 선정 완료를 명확히 표시하고, 목록에서는 해당 건을 제거해 다음 단계 이동을 체감할 수 있게 했다.
   - MR 반려·협력사 거절 사유는 차수 아래 돋보기 버튼의 통합 이력 모달에서 회차별로 확인하도록 정리했다.

3. 로그인 및 공통 UI
   - 로그인 배경에 마우스 반응형 도트와 다중 노이즈 파형 기반의 파도 애니메이션을 추가했다.
   - 신규 MR 모달, 알림·검색, 도움말 버튼, 버튼 및 상태 색상 전반을 BiddingFlow 모노크롬 톤에 맞게 정리했다.

4. 검증
   - npm run build 통과
   - npm run lint 통과
