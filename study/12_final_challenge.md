# 12. 최종 과제 (AI 도움 없이 도전)

이 과제는 AI(나, Claude)의 도움 없이 직접 설계하고 구현해보기 위한 것이다. **구현 방법은 여기 적지 않는다.** 막히면 이 저장소의 `study/00~11` 문서와 실제 BiddingFlow 소스코드를 참고 자료로만 사용하라 — 코드를 복사하지 말고 "이 프로젝트는 이런 상황을 어떻게 풀었더라"를 떠올리는 용도로만 써라.

## 과제: "개인 뉴스/공시 모니터링 및 요약 알리미"

**시나리오**: 당신은 특정 주제(관심 있는 회사, 기술 분야, 취미 등 자유롭게 정하라)에 대한 뉴스나 공개 정보를 매일 자동으로 수집하고, 중요도를 판단하고, 중요한 것만 요약해서 알려주는 개인용 도구를 만든다.

### 필수 조건

1. **새로운 주제**: BiddingFlow의 구매/조달 도메인과 무관한, 당신이 직접 정한 주제여야 한다.
2. **Python 사용**.
3. **외부 API 사용**: 최소 1개의 실제 외부 API(뉴스 API, RSS, 공공데이터포털, 특정 웹사이트의 공식 API 등)에서 데이터를 가져와야 한다.
4. **데이터 처리**: 가져온 원본 데이터를 정제/정규화하는 단계가 있어야 한다(중복 제거, 필드 추출, 필터링 등).
5. **AI/LLM 사용**: 가져온 항목 중 "중요한 것"을 판단하거나 "요약"을 만드는 데 LLM을 최소 1곳 사용해야 한다. 반드시 구조화된 출력(JSON)을 요구하고, 파싱 실패에 대비해야 한다.
6. **Workflow 또는 Agent 구성**: 최소 3단계 이상의 흐름(예: 수집 → 필터링 → AI 판단 → 요약 → 발송)이 있어야 한다. LangGraph를 쓸지, 평범한 함수 체인을 쓸지는 스스로 판단하라 — **어느 쪽을 선택했든 "왜 그렇게 선택했는지"를 설명할 수 있어야 한다** (04번, 08번 문서의 판단 기준을 스스로 적용해보라).
7. **오류 처리**: 최소 다음 세 가지 실패 상황에 대해 프로그램이 죽지 않고 적절히 대응해야 한다 — (a) 외부 API 호출 실패, (b) LLM 응답 파싱 실패, (c) 예상과 다른 형식의 데이터가 들어옴.
8. **구조화된 프로젝트 구성**: 기능별로 파일/폴더를 나눠라(BiddingFlow의 `integrations/`, `nodes/`, `services/` 같은 구분을 참고해 당신만의 구조를 설계하라). 모든 코드를 파일 하나에 몰아넣지 마라.

### 권장하지만 필수는 아닌 것

- 결과를 보여주는 간단한 화면(콘솔 출력이어도 좋고, 원한다면 웹 화면을 만들어도 좋다).
- 환경변수로 API 키/설정을 분리하고 `.env.example`을 함께 제공.
- 실행 결과를 파일이나 DB에 저장해 "이전에 이미 본 항목"을 중복 알림하지 않게 하는 것(멱등성 — 06번 문서의 원칙을 떠올려라).

### 하지 말아야 할 것

- BiddingFlow의 코드를 복사해서 이름만 바꾸는 것.
- LLM에게 "네가 알아서 다 해줘" 식으로 전체 로직을 통째로 위임하는 것 — 무엇을 규칙으로 처리하고 무엇을 AI에게 맡길지 스스로 설계해야 한다.
- 이 과제를 시작하기 전에 이 문서 이후의 답을 찾는 것.

## 평가 기준

과제를 완성한 뒤, 아래 기준으로 스스로(또는 동료에게 부탁해) 채점해보라. 이 기준들은 BiddingFlow 코드에서 실제로 관찰되는 좋은 습관들을 일반화한 것이다.

| 기준 | 확인할 질문 |
|---|---|
| **요구사항 분석** | 이 도구가 해결하는 문제를 한두 문장으로 명확히 설명할 수 있는가? |
| **폴더 구조 설계** | 폴더/파일 이름만 보고 "이 코드가 어디 있을지" 추측할 수 있는가? (05번 문서 3번 "왜 파일을 나눴는가" 기준) |
| **함수 설계** | 함수 하나가 여러 가지 일을 하고 있지는 않은가? 순수 함수와 부작용이 있는 함수가 뒤섞여 있지 않은가? |
| **데이터 구조** | 외부 API 응답, 내부 처리 중 데이터, 최종 출력의 형태가 각 단계에서 명확히 정의되어 있는가(타입힌트/TypedDict 등)? |
| **API 연결** | 외부 API 호출이 한 곳(모듈)에 모여 있는가, 아니면 여러 파일에 흩어져 있는가? |
| **AI 사용 이유** | "왜 이 지점에 AI가 필요했는가"를 규칙 기반으로는 안 되는 이유와 함께 설명할 수 있는가? |
| **에러 처리** | 위 필수조건 3가지 실패 상황을 실제로 강제로 발생시켜봤을 때 프로그램이 죽지 않는가? |
| **코드 가독성** | 다른 사람(또는 6개월 뒤의 당신)이 이 코드를 처음 봐도 각 파일의 역할을 짐작할 수 있는가? |
| **유지보수성** | "수집 대상을 다른 API로 바꾼다면 몇 개의 파일을 고쳐야 하는가?"에 스스로 답할 수 있는가? 답이 "1~2개"에 가까울수록 좋다. |

이 과제를 AI 도움 없이 스스로 완성할 수 있다면, 당신은 이 학습 자료의 목표였던 **"새로운 문제를 보고 처음부터 서비스로 완성하는 능력"**을 갖춘 것이다.
